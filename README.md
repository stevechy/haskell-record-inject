# Introduction

This is a PoC of the way I'd like to use dependency injection in Haskell with a Yesod framework example.

A lot of these ideas come from the `registry` <https://github.com/etorreborre/registry> library.
It is probably possible to implement the same functionality with `registry` but I have some ideas around 
the library ergonomics that are easier to express in a code example.

The main features I want out of a dependency injection library are:
- A new dependency can be set up without touching the injector configuration. This makes things faster when you need to set up a service and a data dependency at the same time. It also reduces merge conflict issues where the injector is configured.
- Adding new dependency to an existing value is easy to do and will generally auto-merge if someone else adds another one at the same time
- It is easy to swap out dependencies in the source code for tests.
  - Building the dependency graph once when the app starts is ok. So features like scopes <https://github.com/google/guice/wiki/scopes> and anything that changes dependencies at runtime are not needed.

Using structures of records and dependency injection results in some not-so-elegant workmanlike Haskell.
For me that is ok.
If the plumbing code is ugly but convenient then I can focus on making the cool stuff elegant.

To test it out I added it to the yesod example project generated by <https://github.com/yesodweb/stack-templates/blob/master/sqlite.hsfiles> 

# Proof of Concept solution

To give a way for the injector to create a dependency without explicit configuration I added a typeclass.
This ended up requiring the typeclass to be defined even for dependencies that need to be initialized outside the injector.
So I added an option to return an error in the default provider.
Maybe there's a better way of doing that but it's also a nice feature.

```
class (Data.Typeable.Typeable a) => Dependency a where
  defaultProvider :: Injector IO -> IO (Either InjectionError a)
```

The generated yesod example uses a lazy eval trick to initialize the db connection pool.
To use that pool I added a wrapper type that I specified to return an error as the default.

```
data SqlDbPool = SqlDbPool {
    sqlDbPool :: Data.Pool.Pool Database.Persist.Sql.SqlBackend
}

instance Data.Injector.Dependency SqlDbPool where
    defaultProvider = Data.Injector.provideNothing
```

Now the pool can be added explicitly.

```
  let injectorConfig =
        Data.Injector.emptyConfig
          & (Data.Injector.addProvider $ Data.Injector.provideValue Db.Pool.SqlDbPool {sqlDbPool = pool})
          & id
  injector <- Data.Injector.newInjector injectorConfig
```

This manually configured dependency requires updating the injector configuration but the idea is to make it easy for simple dependencies and possible for the tough ones.

To add a simple dependency I can use Template Haskell to automate and hide the injector ops.

```
data Deps = Deps {
    sqlPool :: Db.Pool.SqlDbPool
}

Data.Injector.TH.mkDependencyProvider 'Deps
```

`mkDependencyProvider` will make a function called `$(recordConstructor)Provider` that calls `Data.Injector.getInstance` for every field in the record and combines the results.
`Data.Injector.getInstance` will try the cache, then the configuration, and then the typeclass to generate the requested dependency.

```
data LeafDependency = LeafDependency {}

instance Data.Injector.Dependency LeafDependency where
  defaultProvider _ = fmap Right $ do
    return $ LeafDependency {}

data RecordTest = RecordTest
  { aLeaf :: LeafDependency
  }

mkDependencyProvider 'RecordTest

-- Produces:
recordTestProvider ::
  Data.Injector.Injector GHC.Types.IO
  -> GHC.Types.IO (GHC.Internal.Data.Either.Either Data.Injector.InjectionError Main.RecordTest)
recordTestProvider
  = \ injector_a2eO
      -> do aLeaf_a2eP <- Data.Injector.getInstance injector_a2eO ::
                            GHC.Types.IO (GHC.Internal.Data.Either.Either Data.Injector.InjectionError Main.LeafDependency)
            GHC.Internal.Base.pure
              (GHC.Internal.Data.Either.Right Main.RecordTest
                 GHC.Internal.Base.<*> aLeaf_a2eP)
```

Applied to a slightly more realistic example:

```
data Deps = Deps {
    sqlPool :: Db.Pool.SqlDbPool
}

Data.Injector.TH.mkDependencyProvider 'Deps


data UserService = UserService {
    printHello :: IO ()
}

instance Data.Injector.Dependency UserService where
    defaultProvider = Data.Injector.inject depsProvider (fmap Right . newUserService)

newUserService :: Deps -> IO UserService
newUserService Deps{..} = do
    return $ UserService {
        printHello = do
            results <- Db.Pool.runSqlDbPool sqlPool $ (selectList @User []  [])
            putStrLn $ "Hello World Users: " ++ (show $ length results)
    }
```

To add a dependency just add a field to the local `Deps` record with the required imports.
Then I can define a `newUserService` function that doesn't know anything about the injector.
This can be used in tests where dependencies are provided manually.
Using the `RecordWildCards` definition style from <https://github.com/etorreborre/registry/blob/main/doc/boilerplate.md> would also be a nice way to clean up this example.


Finally to swap out dependencies just add a provider configuration to the injector configuration.
This could be useful for say an integration test that you want to hit the database but not an external API.

```
  let injectorConfig =
        Data.Injector.emptyConfig
          & (Data.Injector.addProvider Service.App.otherUserServiceProvider)
          & (Data.Injector.addProvider $ Data.Injector.provideValue Db.Pool.SqlDbPool {sqlDbPool = pool})
          & id
```
